参加ガイド — キーが届いたら最初の5分

守（まもり）に参加する会社の担当者向けです。セキュリティの専任がいなくても、ここに書いた順番で始められます。

参加ガイド動画（約2分15秒）。製品の紹介は下の紹介動画へ。

必要なもの

MacかLinuxのパソコンと「ターミナル」（文字で命令を打つアプリ。WindowsはWSL）／Python 3.9以上／curl。追加のソフトは要りません。Macで初めて python3 を使うときは「コマンドライン・デベロッパ・ツール」を入れる案内が出るので、そのまま入れてください。

いちばん簡単：ふだん使っている AI に入れる

Claude Code・Codex・Sente のどれかを使っているなら、コマンドを1行貼るだけで始められます。入っているものを自動で見つけて、全部に登録します。

1

ターミナルにこの1行を貼る

curl -fsSL https://mamori.teai.io/install.sh | bash

攻撃情報を読むだけなら鍵は要りません。共有もするときは、先に鍵を発行して、こう貼ります：

curl -fsSL https://mamori.teai.io/install.sh | MAMORI_KEY='受け取った鍵' bash

鍵は ~/.config/mamori/key（本人だけが読める設定）に保存され、AI の設定ファイルには書きません。最後に「✅ 脅威情報を取得できました」と出れば成功です。

2

AI を開き直して、話しかける

「Mamori で最新の攻撃情報を教えて」
「Mamori で共有されている攻撃の手口を見せて」（鍵が必要）
「この攻撃を Mamori に共有して：/wp-login.php への総当たり」（鍵が必要）
「Mamori で守りを固めて」（この端末の設定を点検し、安全な項目だけ直します）

読むだけの操作は確認なしで動きます。共有するときは毎回、AI が送ってよいか確認します。社名・ドメイン・人の名前は入れないでください（IPの末尾とメールアドレスはハブ側でも自動で伏せます）。

3

外すとき

curl -fsSL https://mamori.teai.io/install.sh | bash -s -- --uninstall

特定の AI だけに入れる：| bash -s -- --only claude（claude / codex / sente をカンマ区切り）。それ以外の AI ツールは、MCP 設定に python3 ~/.mamori/kit/mamori/mcp/mamori_mcp.py を登録すれば使えます。

手順（ターミナルだけで使う場合）

0

見るだけなら登録不要

いま出ている脅威の一覧は誰でも読めます → 最新の脅威を見る

1

鍵（専用キー）を発行する

鍵の発行・管理でメールアドレスを入れると、ログイン用のリンクが届きます。開いて「新しい鍵を発行する」を押せば、その場で鍵が出ます（ベータ期間中は無料）。会社のドメインのメールなら、参加している会社の共有（緑）まで見られます。

鍵はパスワードと同じです。表示されるのは発行したときの1回だけなので、パスワード管理ソフトに保存してください。なくしたり漏れたかもしれないときは、同じ画面で止めて、新しく発行できます。

2

照合キットを取り出す

cd ~
curl -sL https://mamori.teai.io/kit.tar.gz | tar xz
cd mamori

ホームフォルダに mamori というフォルダができます。

3

キーが使えるか確かめる

export MAMORI_KEY='受け取ったキー'
bash tools/check-key.sh

"ok": true と出れば準備完了です。"ok": false のときはキーの写し間違いを確認し、それでもだめなら連絡してください。

4

自社の製品を書いて、照合する

cp examples/inventory.example.json inventory.json
open -e inventory.json   # Macの「テキストエディット」で開く（Linuxは nano inventory.json）
# 見本のうち使っていない製品の行は消し、使っている製品は見本の行をコピーして名前だけ書き換える
bash run.sh

製品名は英語で、版の数字を付けずに（○ WordPress　× ワードプレス　× WordPress 6.4）。書き方を間違えると、何行目が違うかを日本語で表示します。見本とかっこ・カンマを見比べてください。

結果は data/reports/ にできます。一致が0件でも「安全」という意味ではありません。名前の書き方を確かめ、レポートの「直近7日の新着」にも目を通してください。

「要対応」は、使っている製品名が一致し、かつすでに攻撃に使われている（CISA）か、急ぎの注意喚起（JPCERT/CC）が出ているもの。「要確認」は名前だけ一致したものです。

要対応が出たら：レポートの手順の下書きを読み、自社のバージョンが対象か確かめて、対象なら更新してください。守は設定を勝手に変えません。

毎朝9時に自動で動かす例（crontab -e に1行）:

0 9 * * * cd ~/mamori && bash run.sh >> data/cron.log 2>&1
5

攻撃を見つけたら共有する

bash tools/share.sh "wp-login.php への総当たり" 412 GREEN

ターミナルを開き直したときは、先に export MAMORI_KEY='受け取ったキー' をもう一度実行してください。

「何を」「何回」「どの範囲に」の3つだけです。共有する範囲は信号の色（TLP）で選びます。迷ったら緑（GREEN）。

色見られる人
白 CLEAR誰でも（公開）
緑 GREEN参加している会社
黄 AMBER運営が確認した一部の会社だけ
赤 RED送れません（ハブが受け付けません）

ハブはIPアドレス（IPv4）の末尾を伏せ、メールアドレスらしき文字を消し、時刻を1時間単位にし、会社名の代わりに記号を付けて保存します。IPv6アドレス・自社のドメイン・社内のサーバー名・人の名前は、送る前にご自身で消してください。観測は90日で自動削除されます。

6

ほかの会社の共有を見る

bash tools/feed.sh

ほかの参加者が共有した攻撃（自分のキーで見られる色の範囲・直近90日）が新しい順に出ます。同じ言葉が自社のサーバーのアクセス記録にあれば、その送信元を止め、あなたも共有してください。

止める場所の例：レンタルサーバーやクラウドの管理画面の「IP制限」「WAF」／WordPress のセキュリティ設定。送信元は末尾を伏せた範囲（/24）で表示されるので、範囲ごと止めるときは取引先や自社の利用者を巻き込まないか確かめてください。

困ったとき

  • キーをなくした・漏れたかもしれない → 鍵の発行・管理で、すぐに止めて新しく発行できます（ログインできないときはお問い合わせへ。24時間以内に止めます）。
  • やめたい → 同じくお問い合わせへ。7日以内にキーを止め、御社の共有データを削除します。
  • 決まりごと：利用規約・データの取り扱い ／ キー管理の手順

照合は製品の名前で行います。バージョンまでは見ないので、最後の判断は御社でお願いします。対象外と判定されたもの（関係なし）はレポートに載りません。
